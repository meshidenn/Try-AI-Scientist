# PDFパースプロジェクトの結論

## 結論

現時点では、PDFの文字・座標情報とページ画像を組み合わせるhybrid方式を採用するのが最も妥当である。PDF parseは文字列と座標の取得に強く、画像入力は列、表、図、レイアウトの把握に有効である。両者を組み合わせることで、文字の再現性と視覚的な構造理解を補完できる。

ただし、hybrid方式がすべての文字評価で常に最良という意味ではない。parse-firstが単純な本文文字列の評価で上回る場合もあるため、本文、数値、表、図を分けて評価する必要がある。

## わかったこと

### 1. hybrid方式が有力である

画像だけを入力するimage-firstよりも、PDF parse結果と画像を同時に入力するhybridの方が、数値の再現に有効だった。parse結果から得られる文字・座標情報が、画像だけでは読み落としやすい数値や文字列の補助になる。一方、画像はPDF parseだけでは扱いにくい列配置、表、図の視覚情報を補える。

したがって、今後の基本方式は次の役割分担とする。

- PDF parse: text、座標、ページ番号、text line、表候補の取得
- 画像: レイアウト、列、表、図、装飾、画像内文字の確認
- VLM: parse情報と画像を照合したMarkdown化

### 2. 文字の欠落には1-gram回収率が有効である

PDF側の1-gramのうち、出力にも存在する割合（`cov`）を見ることで、出力に含まれていない文字の種類を検出できる。欠落検出では、出力側一致率（`out`）よりPDF側回収率（`cov`）を主に見るべきである。

ただし、1-gramは文字の存在だけを評価する。文字の順序、位置、出現回数、表セルとの対応までは保証しない。そのため、1-gramは欠落検出、2〜10-gramは文字列の連続性・忠実度の補助指標として使い分ける。

### 3. n-gramの評価単位はPDF blockではなくtext lineが適切である

PDFの同じblock内に、視覚上は別列にある文字列が含まれることがある。決算説明会資料 p8の「日本」「北米」「欧州」がその例である。block全体を連結すると、「日本北米」「北米欧州」のような画像上存在しない文字列が評価対象になる。

したがって、PDFは`get_text("dict")`から取得した座標付きtext lineを単位とし、lineを跨ぐn-gramを生成しない。出力側もMarkdownの行・表セル単位を跨がない。

### 4. 数字と記号は通常の本文文字評価から分離する

数字は財務情報として重要だが、本文文字のn-gram精度に混ぜると評価の意味が曖昧になる。数字はnumeric token、単位、セル位置、年度列などを別に評価する。

記号・句読点・装飾線も、通常の本文文字評価からは除外するのが望ましい。必要な場合は、Markdown構造、表罫線、箇条書き、括弧などの構造要素として別metricにする。

### 5. 表と図は文字n-gramだけでは評価できない

文字n-gramは文字列の欠落や誤変換を確認する補助指標であり、表や図の構造を評価する指標ではない。

表では、次の項目を別に評価する必要がある。

- 行数・列数
- ヘッダとデータ行の対応
- セル位置
- rowspan / colspan
- セル内テキスト
- 数値と単位の対応

図では、次の項目を別に評価する必要がある。

- 図・パネル数
- 図中ラベルのprecision / recall
- ノードや要素の数
- 矢印・線の接続関係
- 左右・上下などの相対配置
- 凡例・キャプション

表・図の評価では、文字列一致を補助指標とし、構造・関係・配置を主指標にする。

### 6. PDF parseだけで扱える範囲とOCRが必要な範囲は異なる

text layerを持つPDFの本文については、OCRは必須ではない。PDF parseで文字、座標、line、画像object、vector drawingを取得できる。

一方、次の場合はOCRまたは画像認識が必要になる。

- スキャンPDFでtext layerがない
- 図や画像の中に文字がある
- ベクター図形の意味を解釈する
- 表の罫線や図の接続関係を画像から確認する

OCRは文字を読むための手段であり、表構造や図の意味を単独で保証するものではない。

### 7. 長い表・複雑な図はページ全体の一括処理に向かない

統合報告書のような複雑なページでは、出力token上限や情報量の多さにより、本文・表・図の一部が欠落しやすい。今後はページ全体を一度に変換するのではなく、本文、表、図、キャプションを座標cropまたはchunk単位で処理し、後段で構造化mergeする必要がある。

## 採用する評価方針

今後の評価は、次のように分離する。

| 対象 | 主な評価 |
| --- | --- |
| 本文文字 | text line単位の1-gram `cov` |
| 文字列忠実度 | 2〜10-gramの`out`、`cov`、F1 |
| 数値 | numeric token、単位、セル位置、年度列 |
| 表 | 行列構造、セル対応、rowspan / colspan |
| 図 | ラベル、要素、接続関係、相対配置 |
| ページ全体 | ページ順、本文・表・図の対応、欠落領域 |

## 適用範囲と注意

ここでの結論は、Toyota資料の代表ページとPDF text layerを用いた評価に基づく。PDF text layer自体が誤っている場合、文字評価のreferenceも不完全になる。また、現時点のn-gram評価は人手goldではなく、PDF parse結果を正解とするproxyである。

したがって、最終的な品質判断には、代表的な表・図について人手で作成したgold manifestを追加する必要がある。
