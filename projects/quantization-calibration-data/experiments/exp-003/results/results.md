# Results

## Summary

`exp-003` ran the real-corpus NVFP4 W4A4 calibration-domain pilot for `Qwen/Qwen3-4B-Instruct-2507`.

Completed stages:

1. Built real calibration/evaluation JSONL files from UltraChat, MBPP, and GSM8K.
2. Quantized three NVFP4 W4A4 variants using 64 real calibration samples per domain.
3. Evaluated base and all three quantized variants with held-out real-corpus NLL on `general_chat`, `code`, and `math_reasoning`.
4. Ran a small generation task pilot on GSM8K exact match and MBPP pass@1 using the existing checkpoints.

Main NLL result: all three NVFP4 variants have higher NLL than the base model on all three evaluation domains. Matched-domain calibration did not produce the best quantized NLL in any of the three domains in this pilot.

Small task-pilot result: GSM8K exact match is too small to separate variants clearly at 4 samples, while MBPP pass@1 shows a drop for the `code`-calibrated and `math_reasoning`-calibrated variants. This task result is a smoke metric, not a benchmark-grade estimate.

This is stronger than the synthetic smoke test in `exp-002`, but still a small pilot: each calibration domain used 64 samples and each evaluation domain used 12 samples.

## Setup

- Base model: `Qwen/Qwen3-4B-Instruct-2507`.
- Quantization: LLM Compressor `oneshot` with `QuantizationModifier(targets="Linear", scheme="NVFP4", ignore=["lm_head"])`.
- Calibration samples: 64 per domain.
- Quantization max sequence length: 2048.
- Evaluation samples: 12 per domain.
- Evaluation max length: 768.
- NLL metric: mean next-token negative log likelihood, lower is better.
- Task pilot: 4 GSM8K samples and 4 MBPP samples per model.
- Task generation limits: GSM8K `max_new_tokens=64`, MBPP `max_new_tokens=96`.
- MBPP execution: restricted subprocess with 2 second timeout per generated solution.

## Datasets

| domain | dataset | config | split | calibration samples | evaluation samples |
| --- | --- | --- | --- | ---: | ---: |
| `general_chat` | `HuggingFaceH4/ultrachat_200k` | `` | `train_sft` | 64 | 12 |
| `code` | `google-research-datasets/mbpp` | `full` | `train` | 64 | 12 |
| `math_reasoning` | `openai/gsm8k` | `main` | `train` | 64 | 12 |

The evaluation files are held-out slices generated by `workspace/build_real_datasets.py`. For math reasoning, calibration uses GSM8K train and evaluation uses GSM8K test.

## Metrics

Primary metric: mean NLL over held-out real-corpus evaluation texts. Lower is better.

Secondary metric: perplexity, computed as `exp(mean_nll)`. Lower is better.

Task smoke metrics:

- GSM8K exact match with numeric answer extraction. Higher is better.
- MBPP pass@1 using generated code extraction plus restricted assert execution. Higher is better.

An initial task run with 8 samples and longer generation was manually interrupted because Transformers/compressed-tensors NVFP4 A4 generation made the accuracy evaluation impractically slow. The completed task artifact uses 4 samples per task.

## Task Pilot Results

GSM8K exact match and MBPP pass@1 over 4 samples per task:

| model | GSM8K exact match | MBPP pass@1 |
| --- | ---: | ---: |
| `base` | 1/4 = 0.25 | 4/4 = 1.00 |
| `nvfp4_real_general_chat` | 1/4 = 0.25 | 4/4 = 1.00 |
| `nvfp4_real_code` | 0/4 = 0.00 | 3/4 = 0.75 |
| `nvfp4_real_math_reasoning` | 1/4 = 0.25 | 2/4 = 0.50 |

The task pilot does not support a matched-domain advantage. The `code`-calibrated variant did not improve MBPP pass@1 in this 4-sample run, and the `math_reasoning`-calibrated variant did not improve GSM8K exact match.

## Failures And Negative Results

- Matched-domain calibration did not win in any evaluated domain.
- All NVFP4 variants were worse than the base model on NLL for all evaluated domains.
- The small task pilot did not show a matched-domain win.
- The `code`-calibrated and `math_reasoning`-calibrated variants lost MBPP pass@1 relative to base in the 4-sample task pilot.
- The evaluation is small: 12 examples per domain.
- The task pilot is very small: 4 examples per task.

## Notes For Reviewer

This experiment changes calibration data domain while keeping base model, quantization scheme, calibration sample count, and evaluation set fixed. It supports conclusions about this small real-corpus NLL pilot and a very small task smoke pilot only; it does not support production-quality claims.
