# Results

## Summary

`exp-002` now has two completed pilot stages:

1. NVFP4 W4A4 quantization completed for three calibration domains on `Qwen/Qwen3-4B-Instruct-2507`.
2. A small held-out synthetic NLL evaluation completed for the base model and all three NVFP4 variants.

This pilot does **not** support the simple hypothesis that matched calibration data is always best. On the current tiny synthetic evaluation set, all NVFP4 variants have lower NLL than base on `general_chat`, while all variants have higher NLL than base on `code` and `math_reasoning`. Among quantized variants, the best NLLs were `nvfp4_code` on `general_chat`, `nvfp4_general_chat` on `code`, and `nvfp4_general_chat` on `math_reasoning`.

These findings are only pilot evidence. The calibration and evaluation sets are synthetic and small, so this should be treated as a pipeline and smoke-test result, not a final claim about real calibration-domain effects.

## Setup

- Host GPU: `NVIDIA GB10`, CUDA `13.0`, driver `580.95.05` as recorded in `logs/preflight.json`.
- Python: 3.12.12 via `uv`.
- Key installed packages: `torch==2.12.0`, `llmcompressor==0.12.0`, `transformers==5.10.1`, `datasets==5.0.0`.
- Pilot base model: `Qwen/Qwen3-4B-Instruct-2507` from local Hugging Face cache.
- Quantization: LLM Compressor `oneshot` with `QuantizationModifier(targets="Linear", scheme="NVFP4", ignore=["lm_head"])`.
- Weight precision: FP4.
- Activation precision: FP4 in the quantization recipe.

## Calibration Dataset

The pilot calibration data uses synthetic prompt JSONL files generated by `workspace/build_calibration_sets.py`. These are pipeline validation samples, not final real-world calibration corpora.

| calibration_domain | file | samples | content style |

## Evaluation Dataset

The pilot quality evaluation uses separate held-out synthetic JSONL files generated by `workspace/build_evaluation_sets.py`. They are not the same files as the calibration data.

| evaluation_domain | file | samples | note |
| --- | --- | ---: | --- |
| `general_chat` | `artifacts/evaluation/general_chat.jsonl` | 12 | short Japanese/English chat and instruction responses |
| `code` | `artifacts/evaluation/code.jsonl` | 12 | small programming explanations and code snippets |
| `math_reasoning` | `artifacts/evaluation/math_reasoning.jsonl` | 12 | simple arithmetic and reasoning solutions |

## Metrics

Primary executed metric after evaluation: mean next-token negative log likelihood (NLL) on held-out synthetic evaluation texts. Lower is better.

Secondary reported metric: perplexity, computed as `exp(mean_nll)`. Lower is better.

The evaluation uses up to 12 samples per domain and `max_length=512`.

## Failures And Negative Results

- First quantization attempt failed because `llmcompressor.oneshot` expected a Hugging Face `Dataset`, but the script passed a Python list. The script was fixed to use `datasets.Dataset.from_list` and to pass `tokenizer` explicitly.
- The first attempt to generate evaluation data with sandboxed `uv run` failed with `bwrap: loopback: Failed RTM_NEWADDR: Operation not permitted`; it succeeded with an approved escalated run.
- Matched calibration did not win on any of the three synthetic evaluation domains. This is a negative or inconclusive pilot result for the matched-domain hypothesis.
- No exact-match, pass@1, human preference, long-context, or multilingual evaluation has been run yet.

## Notes For Reviewer

This run validates an end-to-end NVFP4 W4A4 calibration-domain experiment path on the local GB10 environment: calibration data generation, quantization, held-out evaluation data generation, NLL evaluation, logging, and result summarization.

The current evidence is intentionally weak because both calibration and evaluation data are tiny synthetic pilot sets. Do not generalize these numbers to Red Hat/NVIDIA production NVFP4 recipes or to real LLM benchmarks.
