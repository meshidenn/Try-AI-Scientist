# Survey Update: Spaceship Titanic Modeling Strategy

## Scope

This update extends the initial benchmark-selection survey into a practical
modeling plan for when the official Kaggle CSV files are available.

## Added Understanding

Spaceship Titanic should be treated as a small mixed-type tabular classification
benchmark. The likely highest-yield improvements are not exotic models first,
but:

- structured identifier features from `PassengerId` and `Cabin`,
- spending aggregates such as `TotalSpend` and `NoSpend`,
- missingness indicators,
- categorical-native or tree-ensemble models,
- validation diagnostics that account for passenger groups.

## Model Implications

The immediate scikit-learn path is:

- RandomForest baseline,
- ExtraTrees comparison,
- HistGradientBoosting comparison with categorical dtypes and native `NaN`
  handling where practical.

Optional later path:

- CatBoost for categorical-heavy tabular modeling,
- LightGBM for efficient boosted trees and categorical splits.

These optional dependencies should be added only through `uv add` and only when
the scikit-learn baseline is stable.

## Experiment Recommendations

1. Run official-data baseline with current RandomForest pipeline.
2. Add a compact feature bundle: group, cabin, spending, missingness.
3. Compare RandomForest, ExtraTrees, and HistGradientBoosting under identical
   folds.
4. Add group-aware CV diagnostic using `GroupId`.
5. Add CatBoost or LightGBM only after the above evidence is archived.

## Risks

- Synthetic fixture results do not imply real Kaggle performance.
- Passenger-group leakage can make ordinary stratified CV optimistic.
- Public leaderboard feedback should not drive uncontrolled iteration.
