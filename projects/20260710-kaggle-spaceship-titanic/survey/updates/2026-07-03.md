# Survey Update: Improving Beyond exp-006 / exp-008

## Trigger

exp-008 improved local CV from 0.808810 to 0.812261, but public leaderboard score
dropped from 0.803830 to 0.802430. This update investigates what kinds of
changes are more likely to improve the public score from here.

## Sources Checked

- Kaggle notebook list sorted by votes via Kaggle API.
- `krishnaharish1/spaceship-titanic-feature-engineering-lgbm`.
- `georgymamarin/agents-grading-agents-spaceship-titanic-mle-bench`.
- `fernaandodantas/lgbm-0-8066-score-top-7-solution`.
- `gusthema/spaceship-titanic-with-tfdf`.
- Kaggle topics `716052`, `712563`, and `560289`.

## Findings

### 1. Domain imputation should come before more tuning

The strongest low-risk change is bidirectional CryoSleep/spending imputation:

- `CryoSleep == True` implies missing spend values should be 0.
- Positive spend implies missing `CryoSleep` should be False.
- Zero total spend with missing `CryoSleep` is evidence for True.

This is not just a modeling trick; it follows the dataset semantics. Our current
pipeline has missing indicators and spending aggregates, but it does not fully
encode this rule before model fitting.

### 2. Spending profile features are underdeveloped

Current features include `TotalSpend`, `NoSpend`, `LuxurySpend`, and
`ServiceSpend`. Public notebooks suggest adding:

- `LogTotalSpend`,
- log transforms for each spend column,
- `NumSpendCategories`,
- per-category spend ratios,
- `BasicSpend = FoodCourt + ShoppingMall`,
- `LuxurySpend = Spa + VRDeck + RoomService`.

These should be tested as a single feature bundle before adding new model
dependencies.

### 3. Model diversity matters more than another tiny HGB tune

Public examples that reach the 0.81+ region commonly use CatBoost, LightGBM,
XGBoost, or TensorFlow Decision Forests. The strongest reproducible notebook
reviewed uses CatBoost + LightGBM + XGBoost with 10-fold OOF predictions and
then compares weighted averaging with stacking.

This aligns with exp-008: a tiny HGB CV gain did not transfer. A different
model family may create less-correlated errors and help an ensemble.

### 4. OOF probabilities are now important artifacts

Future experiments should save:

- OOF probabilities per fold,
- test probabilities per fold,
- model-level CV scores,
- correlation between OOF predictions,
- final threshold and predicted positive rate.

Without probabilities, stacking and threshold diagnostics are hard to audit.

### 5. Threshold tuning is promising but risky

Some public notebooks tune the classification threshold to match a target
positive rate. This may help, but it can overfit public leaderboard feedback.
Treat threshold tuning as a separate experiment:

- choose threshold from OOF accuracy or OOF positive-rate diagnostics,
- record test predicted positive rate,
- submit sparingly.

### 6. Variance and provenance matter

A Kaggle discussion reports repeated agent runs spanning roughly 0.802 to 0.821
and explicitly warns that single submissions can be noisy. For this repository,
the main lesson is not to chase every small CV gain. Preserve code, seeds, OOF
predictions, and submission metadata.

## Recommended Next Experiments

1. `exp-009`: domain imputation + richer spending profile features using
   HistGradientBoosting. No new dependency.
2. `exp-010`: LightGBM with the richer feature set, 10-fold OOF, early stopping,
   and saved probabilities.
3. `exp-011`: CatBoost and XGBoost comparison under the same folds.
4. `exp-012`: weighted average and stacking over OOF probabilities.
5. `exp-013`: threshold tuning / predicted positive-rate calibration.

## Submission Rule

Keep exp-006 public score 0.803830 as the leaderboard baseline.

Submit only if:

- model family or ensemble strategy changes materially, or
- CV improves with lower fold variance and group-aware diagnostic support.

Avoid submitting every small single-model CV gain.
